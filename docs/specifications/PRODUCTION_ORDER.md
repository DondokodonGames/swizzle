# 制作順序 — 遊びの型 → 世界観 → 様式

**この順序を守ることが、似たゲームを作らないための唯一の構造的な手段。**

順序が逆（世界観が先）だと、遊びは手癖の型に落ちる。世界観から発想すると
「ホタルを捕まえる」「星をつかまえる」「妖精を捕まえる」が全部「光った瞬間にタップ」に着地する。
題材だけが違う同じゲームが並ぶのは、発想力ではなく**順序の問題**。

---

## 1. 三段階

### 第1段: 遊びの型（play form）— ここから始める

**「指で何をして、何が起きたら成功・失敗か」だけを決める。**題材・見た目・世界観は一切考えない。

- 型は `MECHANICS_CATALOG_V2.md` の40+ID（`src/ai/code/mechanics-v3.ts` が正）で名指しできること
- **800本すべての型が相異なること**。既存と同じ型・同じ勝ち方なら、それは新作ではない
- 型が薄い／空いている場所から選ぶ（`npm run ai:neta:space`）
- 既存と重なっていないかを確認する（`npm run games:dup`）

合格条件: 型を一文で書いたとき、既存800本のどれとも違うと言い切れること。

### 第2段: 世界観（world）— 型から導出する

型が決まったら、**その型が生む緊張の正体**を一言にし、**その緊張が最も自然に起きる状況**を世界観にする。

```
型: 押している間だけ伸びる。離すと倒れる
 ↓ 緊張の正体: 「どこで離すか」の見極め。行き過ぎても足りなくてもダメ
 ↓ 状況: 対岸に橋を架ける（届かなければ落ちる）
```

- 世界観は型の**言い換え**であって、飾りではない
- フックも型から書く。世界観から書くと「〜する◯◯ゲーム」にしかならない
- 世界観の語彙表（`themes.json` / ledger の THEMES）は**発想の起点ではなく、言葉に詰まったときの参考**

合格条件: 「なぜこの世界観なのか」を型から説明できること。入れ替え可能な世界観は、まだ導出できていない。

### 第3段: 様式（style）— 最後に当てる分類

見た目は**分類**であって発想ではない。世界観に合わせて選ぶのではなく、
**時代様式のどれで作るか**を決める。

- 選択肢は **19パック**（`ARCADE_ART_DIRECTION.md` §2 / 機械可読は `src/ai/code/stylePacks.ts`）。
  ベクタースキャンから現代の広告ゲームまで、実在した各時代のハード表現を網羅してある
- ファイル冒頭に `// スタイル: <ラベル>` を**宣言必須**。v3バリデーターが
  `NO_STYLE_PACK` / `UNKNOWN_STYLE_PACK` で検査する
- 在庫のバランスで選ぶ（同じ様式に偏らせない）。偏りは `npm run games:ledger` の
  「様式の分布」で見える
- 拠点・客層で選んでよい（インバウンド拠点にどの時代が効くかは計測で分かる）
- **様式を変えても別ゲームにはならない**。様式は差別化手段ではない
- パック名にハードウェアの商標を持ち込まない（時代と技法で言い換える）

---

## 2. やってはいけない順序

| 逆順 | 何が起きるか |
|---|---|
| 世界観 → 遊び | 手癖の型（タップ/タイミング）に落ちる。実測で既存ネタの主戦場がそこに寄っている |
| 様式 → 世界観 → 遊び | 見た目だけ違う同じゲームが量産される |
| 遊び → 世界観を**入れ替えて**量産 | これは1本を水増ししているだけ。`--variations 5` 的な発想は禁止 |

---

## 3. 800本への適用

- **型が重複している66〜232本は、型を作り直す**（`npm run games:dup` の振り替え案）。
  世界観を変えても重複は解けない
- 書き換え（WP56）では、割り当て済みの `theme` 列は**参考**に格下げする。
  正しくは「その型から導出した世界観」を書く
- 世界観コメント（`// 世界観:`）が無いゲームが 87.6% ある。型から導出して埋める
